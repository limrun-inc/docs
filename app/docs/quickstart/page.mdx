# Quickstart

This takes about three minutes. You need Node.js 20 LTS or newer; you do not need a Mac.

<Note>
  Setting this up for a coding agent instead? Follow [Set up a coding agent](/docs/agents/cli). It installs the Limrun skills, which walk the agent through the same loop.
</Note>

## Try it in the browser first

The [console](https://console.limrun.com) has a **Playground** that creates and streams an instance without installing anything. Pick an operating system, optionally an app to preinstall, and click **Start**.

## Build and run an app

<Steps>
  <Step title="Install the CLI">
    Install the `lim` package globally with the package manager you use:

    ```bash
    npm  install --global lim
    pnpm add     --global lim
    bun  add     --global lim
    ```
  </Step>

  <Step title="Authenticate">
    On a machine with a browser, log in:

    ```bash
    lim login
    ```

    The CLI opens the console in your browser, completes authentication, and stores the API key in `~/.lim/config.yaml`.

    On a headless host such as a CI runner, a devcontainer, or a cloud agent, create a key instead: open [console.limrun.com/settings](https://console.limrun.com/settings), go to **API Keys**, click **Create Token**, and export it:

    ```bash
    export LIM_API_KEY=lim_...
    ```
  </Step>

  <Step title="Get an iOS project">
    Clone the sample app, or `cd` into an iOS project you already have:

    ```bash
    git clone https://github.com/limrun-inc/sample-native-app.git
    cd sample-native-app
    ```
  </Step>

  <Step title="Build on a cloud Mac">
    Run the build from the project directory:

    ```bash
    lim xcode build .
    ```

    The first run creates an Xcode sandbox, syncs the project to it, and runs `xcodebuild` there. Build logs stream back as they happen. For a project with several schemes, add `--scheme <name>` and either `--workspace <path>` or `--project <path>`.
  </Step>

  <Step title="Run it on a simulator">
    Create a simulator attached to the sandbox:

    ```bash
    lim ios create --attach --reuse-if-exists --label project=quickstart
    ```

    Attaching installs and launches the latest build right away, and every later successful build reinstalls it. The CLI prints the **signed stream URL** and opens it in your browser. The URL carries its own token, so anyone you share it with can watch and control the simulator without signing in.

    <Frame>
      <img src="/images/console/06-ios-app-launched.png" width="300" alt="The sample-native-app running on a remote iOS simulator, showing its 'Hello, world!' first screen" />
    </Frame>
  </Step>
</Steps>

## Drive the app from your shell

Read the screen and act on it with `lim ios` commands. Without `--id`, each command targets the instance you created last in this git repository:

```bash
lim ios screenshot ./screen.jpg
lim ios element-tree
lim ios tap-element --ax-label "Mountains and sun"
```

The element tree lists every label, accessibility identifier, type, and frame on screen. The sample app shows only an image labelled `Mountains and sun` and the text `Hello, world!`, which is why the tap selects that label. Read the tree before each action and select elements from it; selectors keep working when the layout changes, pixel coordinates do not. In your own app, tap a text field first, then type into it with `lim ios type "Hello"`; typing fails when no field has focus.

Change some code and run `lim xcode build .` again. The new build replaces the app on the attached simulator.

## Clean up

Delete both instances when you are done. Without an ID, `delete` removes the last instance of that type the CLI created for you:

```bash
lim ios delete
lim xcode delete
```

Instances you forget are deleted by your organization's inactivity timeout.
