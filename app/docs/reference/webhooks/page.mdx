# Webhooks

Register an organization endpoint to receive events as HTTPS POST requests. Organization administrators and API keys with the `organization:*:*` scope can manage endpoints and read event history. Instance and scoped tokens cannot access these endpoints.

## Register an endpoint

```bash
curl https://api.limrun.com/v1/organizations/ORG_ID/webhook_endpoints \
  -H "Authorization: Bearer $LIM_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "url": "https://your-app.example.com/limrun/events",
    "eventTypes": ["instance.created", "instance.ready", "instance.terminated", "instance.billed"],
    "products": ["ios", "android", "xcode", "gradle"]
  }'
```

Replace `ORG_ID` with the organization TypeID, starting with `org_`. Save `signingSecret` from the response. Subsequent reads omit it. The response's `endpoint.id` identifies the endpoint.

`eventTypes` must contain explicit names from the table below. Optional `products`, `instanceIds`, and `labels` filters all have to match. Each label filter requires an exact key and value match. Empty filters allow all values. Organization billing events have no product or instance unless they were caused by a specific instance, so leave those filters empty when subscribing to organization-wide billing changes.

The URL must use HTTPS and resolve to public addresses. Redirects are not followed.

## Event types

| Event | Meaning |
| --- | --- |
| `instance.created` | A new instance exists. Reusing an existing instance does not create another event. |
| `instance.ready` | The instance first became ready for its public API. |
| `instance.provisioning_failed` | Initialization recorded a terminal asset failure, or the creation flow requested deletion after a readiness failure. The instance may still exist. |
| `instance.termination_requested` | The instance entered deletion, including user requests, inactivity, hard timeout, or owner deletion. |
| `instance.terminated` | Instance teardown reached its final lifecycle step. Billing is separate. |
| `instance.creation_rejected` | Credits, a billing gate, concurrency, or final regional capacity prevented creation. `resourceId` is a request ID; no instance ID is assigned. |
| `instance.billed` | Usage was allocated to credits, subscription minutes, or metered usage. Includes zero-cost usage. This does not mean an invoice was paid. |
| `instance.billing_skipped` | An operator explicitly skipped billing. |
| `instance.billing_failed` | Billing stopped without covering the full usage. Check `partiallyBilled` and `allocations`; some credits or minutes may already have been consumed. |
| `billing.credits_depleted` | Instance billing reduced a positive credit balance to zero. |
| `billing.credits_added` | An operator added organization credits. |
| `billing.allowance_refilled` | A paid invoice refilled a recurring subscription's minutes. |
| `billing.subscription.created` | A subscription creation was processed. |
| `billing.subscription.updated` | A subscription update was processed. |
| `billing.subscription.deleted` | A subscription deletion was processed. |
| `billing.invoice.paid` | An invoice payment was processed. |
| `billing.invoice.payment_failed` | An invoice payment failure was processed. |
| `organization.limits_updated` | Concurrency limits or default instance timeouts changed. |
| `asset.created` | Asset metadata was created. The file may not have been uploaded yet. |
| `asset.updated` | Public asset metadata changed. |
| `asset.deleted` | The asset was removed, including expiry cleanup. |
| `asset.available` | Storage confirmed an uploaded asset version. |
| `distribution.started` | A TestFlight, Play Store, or physical-device installation operation started. |
| `distribution.accepted` | The target accepted the operation. For TestFlight, `acceptanceStage` distinguishes upload commit from a created build record. Play Store acceptance means the edit committed. Device acceptance means the installation command completed. |
| `distribution.failed` | The observed distribution operation failed. |
| `ota.delivery_completed` | The registry finished writing the IPA download. This is not confirmation that iOS installed or launched it. |
| `ota.delivery_failed` | The observed IPA download attempt failed. |
| `ota.expired` | An OTA session's download link expired before a terminal download result was observed. |

Instance termination does not guarantee that physical cleanup, artifact publication, or billing has finished. Termination reasons include `UserRequested`, `InactivityTimeout`, `HardTimeout`, `ProvisioningFailed`, and `Unknown`. Treat this as an open set.

Distribution events include a stable operation ID and available build, asset, or session correlation fields. In-instance distribution events use the instance product (`xcode` or `gradle`); registry Play Store and device events use `android` and `ios`, respectively. A successful TestFlight upload without a verdict wait cannot report Apple's later processing result. OTA attempts are numbered because a device can retry the same session.

## Verify deliveries

Every event uses this envelope:

```json
{
  "id": "evt_...",
  "version": "2026-10-07",
  "type": "instance.ready",
  "organizationId": "org_...",
  "occurredAt": "2026-10-07T12:00:00Z",
  "resourceId": "ios_region_...",
  "product": "ios",
  "instanceId": "ios_region_...",
  "labels": {"suite": "smoke"},
  "data": {"region": "eu-north1", "pool": "iphone"}
}
```

`product`, `instanceId`, and `labels` are optional. Xcode instance IDs retain their `sandbox_` prefix; their event product is `xcode`. Related child instances include `data.parentInstanceId` on lifecycle events when available.

Requests include `Limrun-Event-Id`, `Limrun-Delivery-Id`, and `Limrun-Signature`. The signature is `t=UNIX_SECONDS,v1=HEX_HMAC`. Compute HMAC-SHA256 with the complete signing secret over the timestamp, a dot, and the exact raw request body. Verify before parsing JSON and reject stale timestamps.

```javascript
import { createHmac, timingSafeEqual } from "node:crypto";

export function verifyLimrunWebhook(rawBody, signature, signingSecret) {
  const parts = Object.fromEntries(signature.split(",").map(v => v.split("=")));
  if (!/^\d+$/.test(parts.t ?? "") || !/^[a-f0-9]{64}$/.test(parts.v1 ?? "")) return false;
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;
  const expected = createHmac("sha256", signingSecret)
    .update(parts.t + ".")
    .update(rawBody)
    .digest();
  return timingSafeEqual(expected, Buffer.from(parts.v1, "hex"));
}
```

Acknowledge with any 2xx response after durably accepting the event in your application. Delivery attempts time out after 20 seconds. Each delivery is attempted up to 12 times, with exponential backoff starting at 30 seconds and capped at six hours. A rejected destination is marked failed immediately. Disabling an endpoint pauses pending deliveries and excludes it from new events.

Once recorded, events and delivery jobs are durable. Delivery is at least once and can arrive out of order. Deduplicate by `id`, including manual replays. Events retain the same ID and payload on retry; each attempt gets a fresh signature timestamp. Subscriptions are selected when Limrun records the event. Registration does not replay events already in the log.

Registry sessions and in-instance distribution operations report what they observe. A process stopping before it records an outcome can leave that outcome unreported. An expired OTA session does not cancel an IPA transfer already in progress.

## Inspect and replay

All paths below start with `/v1/organizations/ORG_ID` and use your API key:

| Method and path | Purpose |
| --- | --- |
| `GET /webhook_endpoints` | List endpoints. |
| `GET /webhook_endpoints/ENDPOINT_ID` | Read an endpoint without its secret. |
| `PUT /webhook_endpoints/ENDPOINT_ID` | Replace its URL and filters. Set `enabled: false` to pause. |
| `DELETE /webhook_endpoints/ENDPOINT_ID` | Permanently deactivate the endpoint. |
| `GET /webhook_events` | Read recorded events. |
| `GET /webhook_endpoints/ENDPOINT_ID/deliveries` | Inspect delivery state, attempt count, and the most recent result. |
| `POST /webhook_endpoints/ENDPOINT_ID/deliveries/DELIVERY_ID/replay` | Requeue a delivered or failed event for an enabled endpoint. |

List operations accept `limit` from 1 to 100 and `offset` from 0 to 10000. Replay retains the event and delivery IDs and resets the attempt budget. Pending deliveries cannot be replayed. To replace a lost signing secret, create a new endpoint, save its secret, and delete the old endpoint.

## Confirm an asset upload

After uploading to a presigned asset URL, call:

```bash
curl -X POST https://api.limrun.com/v1/assets/ASSET_ID/complete \
  -H "Authorization: Bearer $LIM_API_KEY"
```

Limrun verifies that the object exists and publishes `asset.available` once per asset and storage entity tag. Repeating completion for the same uploaded version is safe. Xcode builds that report asset metadata call this verification automatically. Other direct uploads must explicitly complete the upload. An availability event describes the verified version at that time; assets can later be overwritten or deleted.

Existing per-build completion webhooks remain separate from organization event subscriptions.
